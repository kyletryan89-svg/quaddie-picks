# DECISIONS.md

Append-only log of decisions made during the build, per SPEC §8 rules.

| # | Date | Decision | Rationale |
|---|------|----------|-----------|
| D1 | 2026-08-26 | Project root `~/quaddie-picks`, npm as package manager | Only npm installed; home dir is an unrelated git repo |
| D2 | 2026-08-26 | Supabase JS v2 + `@supabase/ssr`; anonymous sign-in after passcode check; profiles upsert keyed off `auth.uid()` | Spec §4 auth flow |
| D3 | 2026-08-26 | Realtime via single client subscription on `picks` filtered to the meeting's legs | Spec §6 core feature |
| D4 | 2026-08-26 | Season = rolling 1 Aug–31 Jul from today's date; selector lists seasons present in data | Spec §2 SEASON |
| D5 | 2026-08-26 | R2 security tests = integration tests vs hosted DB using anonymous sign-in sessions; fixtures prefixed `TEST-`; cleanup via service-role key from env only | No Docker locally; policies must be exercised for real |
| D6 | 2026-08-26 | Seed script uses service role to create 5 anon-auth profiles + fixtures | Spec R7 seed requirements |
| D7 | 2026-08-26 | `GROUP_PASSCODE` generated locally; stored in `.env.local`, `.env.example`, Vercel env; referenced only in server action module | Spec §4 + R1 |
| D8 | 2026-08-26 | `vercel.json` pins functions region `syd1` | Spec §3 |
| D9 | 2026-08-26 | Errors render inline in UI; every list has loading/empty states | Spec R6 |
| D10 | 2026-08-28 | `picks` set to `REPLICA IDENTITY FULL` (migration `20260828000000`) | The meeting screen subscribes with `filter: leg_id=in.(…)`. Under the default replica identity a DELETE's WAL record carries only `id`, so Realtime cannot evaluate that filter and drops the event — removing a tip never reached other members. FULL puts the whole old row in the WAL so the filter matches. Verified by probe: filtered channel went from 0 to 1 DELETE received. No new dependency; WAL cost is negligible for 5 users |
| D11 | 2026-08-28 | "A leg's field" for settle validation = runner-number range **1–99**, not the set of runners members tipped | The schema stores no field roster and SPEC §6 forbids adding an input for one. Validating against tipped runners would make a winner nobody backed unrecordable — and SPEC R4 case 6 ("All losses. Nobody hits anything") requires that state to be reachable. 99 rather than a realistic ~24-starter cap because `docs/scoring-examples.md` Example 3 uses runner #77, which M6's own verification enters through the UI |
| D12 | 2026-08-28 | Re-pasting a field goes through a `security definer` RPC, `replace_leg_field()` | The brief requires both "no delete from client" on `runners` and "re-pasting replaces that leg's field". RLS cannot tell a server action from a browser — both carry the user's JWT — so no delete policy can be both absent and present. The RPC holds the delete privilege instead: clients get select+insert only, and the function refuses anonymous callers and any meeting that is not open. Runners that survive a re-paste keep their id, so picks on them survive; only dropped runners lose picks, by cascade |
| D13 | 2026-08-28 | The M8 strip applies to the open and locked meeting screen; the settled result table and leg SPs stay | "Remove all dollar amounts from this screen entirely" is in a section about the picking experience ("No currency, no cost framing"). Applied literally to the settled state it would delete the per-meeting result table, breaking rubric R5 and the M6 regression the same brief requires to pass. Money is gone from every state a member picks in; results remain results |
| D14 | 2026-08-28 | The M0–M7 verification scripts were migrated to the new schema and UI | Not a free choice: M8 drops `picks.runner_number` and removes free-text entry, which is exactly what those scripts wrote and typed. The regression could not otherwise run at all. Every assertion was preserved; only the drive mechanism changed. `scripts/mobile-check.ts` was retired — it was the harness for the mobile-pass M8 that this milestone replaces, and its meeting-screen half drove UI that no longer exists |
| D15 | 2026-08-28 | **Meetings + runners come from the Racing NSW FreeFields feed**, not member input | The brief asked for "the race form guide for the metro meetings on Saturdays" presented on screen. Every bookmaker/racing API probed was bot-walled (TAB resets, Sportsbet/racing.com/racenet 403, Racing Australia Zenedge). The state authority's `racing.racingnsw.com.au/FreeFields/` calendar + acceptances pages are public HTML, no key, and carry the full form guide (number, name, jockey, weight, barrier, benchmark, form, scratchings). Parsed server-side (pure `lib/racedata.ts`) and mirrored into the existing meetings/legs/runners tables on demand, so picks/scoring/settle/leaderboard are untouched |
| D16 | 2026-08-28 | **Melbourne metro is deferred**; the feed is keyed by state so it can be added later | Racing NSW covers NSW only; the VIC equivalents (racingvictoria.com.au / racing.com / racingaustralia.horse) are bot-walled or don't resolve. The user asked for "Sydney + Melbourne" but the group is NSW; shipping Sydney now with a state-keyed feed, VIC as a follow-up drop-in |
| D17 | 2026-08-28 | The quaddie is always the **last four races** of the card; legs carry `race_name`/`race_time`; runners carry form-guide columns; a `comments` table powers the side panel | The user's rule, and what "the quaddie" means in practice. Legs are derived from the calendar so they exist even before acceptances publish; runners arrive once acceptances are out. Runner form detail is display-only, never scored |
| D18 | 2026-08-28 | Anonymous chat user_id is omitted at the **API layer** via a read view, `chat_messages_view`, which nulls `user_id` when `is_anonymous` | The brief demands the response omit `user_id`, "not just hide it in the UI". The client reads only the view (both initial load and on every realtime event it re-fetches through the view), so anonymous rows never carry user_id into the browser. The base table still records `user_id` (RLS delete-own needs it) and its SELECT grant is left intact because Supabase Realtime's RLS check runs against the table |
| D19 | 2026-08-28 | First/second pick ranking goes through a `security definer` RPC, `set_pick_rank()` | Two needs collide: "setting a new 1st clears the old" must be atomic (two client UPDATEs could race the partial unique index), and `picks` deliberately has no UPDATE policy. The RPC clears the old rank and sets the new one in one statement, touches only `rank`, only the caller's own pick, and only while the meeting is open — same trust model as `replace_leg_field` (D12) |
| D20 | 2026-08-28 | A reopen (unlock) is recorded as `reopened_by`/`reopened_at` on the `meetings` row | Simplest audit for "who reopened and when": the row already broadcasts through the meetings realtime channel, so every member's screen shows the reopen line live. Overwritten on each reopen — only the latest matters for the screen |
| D21 | 2026-08-29 | The cron ingestion routes use the Supabase **service role** (`lib/supabase/service.ts`), gated by a `CRON_SECRET` bearer token | A cron job has no user session, so it cannot satisfy the "to authenticated" RLS policies. The service role was previously scripts-only (D7); this scopes it to server-side, secret-gated jobs only — never a client component or user action. The "Sync now" button runs with the member's own session (RLS still applies) |
| D22 | 2026-08-29 | The Ladbrokes provider sync is scoped to **VIC metro only** | The existing Racing NSW FreeFields feed already ingests NSW metro on the list page; ingesting NSW via Ladbrokes too would create duplicate meetings (e.g. "Rosehill" from Ladbrokes next to "Rosehill Gardens" from Racing NSW). The gap this milestone fills is Melbourne (D16) |
| D23 | 2026-08-29 | Automated ingestion uses the **Ladbrokes/Neds Entain affiliates API**, not TAB | The spike (M0) proved TAB is Akamai bot-walled from `syd1` (403) and geo-blocked from `iad1` (HTML). Ladbrokes returns JSON from both regions and is the documented affiliates feed. Field map in `docs/provider-mapping.md` |
| D24 | 2026-08-29 | `winner_sp` = the host-state **"Tote Win" dividend** from the provider's `dividends`, never the fixed odds | Confirmed against two completed Sandown races where the VIC tote win (2.3 / 5.0) differed from `fixed_win` (2.25 / 4.8). Tote win dividends are already total-return-per-$1, matching the app's SP convention. If the host tote win is absent, `winner_sp` stays null and manual entry is required |
| D25 | 2026-09-02 | The leaderboard roster is the five canonical members (`Kyle, Leigh, Steve, Pete, Chris`) and scoring there only pays on the **first pick** — 2nd/3rd picks count only when *every* roster member has a 2nd/3rd in that leg | The group is fixed at five; any other profile (test accounts, re-logins, casing variants) is noise and is filtered via `canonicalRoster()`. "Only pay if the first pick gets up" keeps the ladder a fair comparison of everyone's top pick instead of rewarding whoever boxed the widest. Rank extended to 3 (`set_pick_rank` accepts 1/2/3). The rule is leaderboard-only (`scoreMeetingRanked`); the per-meeting result table still counts every pick so the settle screen matches what was actually tipped |
